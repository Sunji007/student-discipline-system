5.​ รายละเอียดตามโครงสร้างสไลด์ 
5.1 ที่มาและความสำคัญ (บทที่ 1) 
●​ ปัญหาคืออะไร → ปัญหาเกิดกับใคร → ระบบที่พัฒนาช่วยแก้ปัญหาอย่างไร 
●​ ควรมีข้อมูล/สถิติหรือหลักฐานสนับสนุน (ถ้ามี) 
○​ ตัวอย่าง:​
“ระบบเดิมใช้เอกสารในการบันทึกข้อมูล ทำให้ค้นหาข้อมูลล่าช้าและเกิดความซ้ำซ้อน 
จึงพัฒนาระบบ... เพื่อช่วยจัดเก็บ ค้นหา และรายงานข้อมูลอย่างเป็นระบบ” 
5.2 วัตถุประสงค์ (บทที่ 1) 
●​ นำเสนอเป็นข้อ ๆ ตาม Proposal  
5.3 ขอบเขตของระบบ (บทที่ 1) 
●​ นำเสนอประชากรและกลุ่มตัวอย่าง  
●​ นำเสนอขอบเขตงาน (เฉพาะส่วนสำคัญ) เช่น 
○​ ผู้ใช้งานระบบมีกี่กลุ่ม/ประเภท 
○​ ระบบมีฟังก์ชันหลักอะไรบ้าง 
5.4 แนวคิด ทฤษฎี และงานที่เกี่ยวข้อง (บทที่ 2) 
●​ ไม่จำเป็นต้องนำเสนอทุกทฤษฎี เลือกเฉพาะที่เกี่ยวข้องโดยตรงกับการพัฒนาระบบ เช่น 
○​ SDLC

○​ แนวคิดหรือทฤษฎีที่ใช้ในการประเมินระบบ 
●​ งานวิจัยที่เกี่ยวข้อง สรุปเพียง 2–3 งานสำคัญ และบอกว่า “งานวิจัยนี้นำแนวคิดดังกล่าว
มาประยุกต์ใช้ในการพัฒนาระบบ...” 
5.5 วิธีดำเนินการพัฒนา (บทที่ 3) 
●​ การพัฒนาระบบ ให้ใช้ SDLC เป็นแกนกลาง แสดงเป็นภาพ เช่น 
○​ Planning → Analysis → Design → Development → Testing → Implementation 
●​ อธิบายสั้น ๆ ว่าโครงงานนี้ดำเนินการอย่างไรในแต่ละขั้นตอน 
5.6 ผลการวิเคราะห์และออกแบบระบบ (บทที่ 4) 
●​ ไม่ควรใส่ Diagram ทุกตัวที่อยู่ในเล่ม 
●​ เลือกเฉพาะ Diagram สำคัญที่สุด เช่น 
○​ Context Diagram 
○​ Use Case Diagram 
○​ ER Diagram 
○​ Flowchart 
○​ System Architecture 
●​ โดยเลือกประมาณ 1–2 แผนภาพ และอธิบายว่า ​
“จากการวิเคราะห์ระบบ พบว่า ผู้ใช้งานมี 5 กลุ่ม ได้แก่... และมีฟังก์ชันหลัก...” 
5.7 ผลการพัฒนาระบบ ⭐ สำคัญที่สุด (บทที่ 4) 
●​ ส่วนนี้ควรใช้เวลามากที่สุด เพราะเป็น โครงงานพัฒนาระบบ 
●​ แนะนำให้ใช้ ภาพหน้าจอจริงของระบบ แทนข้อความ 
●​ ให้นำเสนอตามกลุ่มผู้ใช้งาน เลือกเฉพาะฟังก์ชันหลัก  
●​ ตัวอย่างลำดับการนำเสนอ 
○​ Login → หน้าหลัก → เพิ่มข้อมูล → ค้นหาข้อมูล → รายงาน 
○​ เลือกเฉพาะ ฟังก์ชันหลักของโครงงาน 4–6 หน้าจอ 
●​ ไม่ควรนำเสนอทุกหน้าจอในระบบ (รายละเอียดฟังก์ชันงานภาพรวม รอสาธิต/นำเสนอ
หลังนำเสนอเสร็จ) 
●​ และควรอธิบายให้เห็นว่า “ระบบสามารถทำอะไรได้ และช่วยแก้ปัญหาเดิมอย่างไร”
